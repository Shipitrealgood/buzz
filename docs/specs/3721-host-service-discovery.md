## F2: one service, one persistent agent context

**Depends on:** F1 for production integration. **Verify:** V1/V2. Root administrator is trusted; agents and their subprocesses are not privileged.

Keep `buzz-paired-agent@<unit>.service`, DynamicUser, `StateDirectory=buzz-agent-<unit>`, 0700 state, and root-controlled `LoadCredential=instance`. Use one context constructor for all modes: HOME is the unit StateDirectory, GROK_HOME is `<HOME>/.grok`, XDG_CONFIG_HOME is `<HOME>/.config`, a private per-unit runtime directory contains sockets, and cwd is HOME. The paths come from systemd and the trusted installed unit, never owner/client fields. Clear inherited environment before every child. Keep the existing explicit Buzz identity/policy environment only for conversation; login/models receive no Buzz signing key or OA in their environment. Provider credential profile must remain `none` (`lib.rs:252–258`).

Use the same unit for three fixed modes: `conversation`, `login`, `models`. Select the mode through a root-owned, bounded execution descriptor loaded as a systemd credential alongside `instance`; it binds unit, agent, enrollment, catalog revision, deployment operation/revision, action nonce and deadline. Default/ordinary start is conversation. A mode descriptor is not a remotely writable command, env map, path, or shell fragment.

The helper serializes selection/start with its existing transaction boundary and refuses login/models while the unit is active, activating, deactivating, or has residual processes. Do not automatically stop a running conversation for a refresh/login. After selecting a mode, start that same unit; the runtime consumes the immutable credentials. For finite modes the runtime supervisor, as the unit main process, sends systemd readiness only after validating the context and establishing child supervision; this means action-started, never authenticated or models-ready. A fast completed action is observed through its correlated result even if the unit is already inactive. Login/model actions are finite and never enable the service for reboot. Disable any prior enablement before entering an explicitly requested finite mode, and do not automatically resume conversation. Cancellation, startup failure and timeout kill the entire owned cgroup; return busy/unconfirmed until stop is actually observed. Cleanup uses the same unit, so the existing tombstone covers every mode. No child can continue a login after a cleanup acknowledgement.

Finite modes must not be retried by `Restart=on-failure`, or restarted as login after boot. Use one fixed root-generated per-instance drop-in, `50-buzz-execution-mode.conf`, whose only finite-mode service setting is `Restart=no`; remove it for conversation, then reload the manager before starting. Keep the action selection in the protected execution credential, not in arbitrary ExecStart text. Extend helper unit-shape verification narrowly: accept only this exact owned path with root ownership, no symlink, and exact permitted bytes for the selected mode; all other drop-ins remain foreign. The helper disables enablement before finite action start and refuses an expired action descriptor at runtime. A runtime crash therefore cannot automatically repeat provider login. Conversation retains its normal restart behavior. Cleanup removes the owned mode artifact and descriptor only after stop/disable is confirmed, keeping its existing tombstone. This is a fixed helper implementation detail, not a client-controlled unit-override facility.

**Concrete filesystem policy:** in the canonical unit, replace ambient host-root visibility with an empty/read-only mount view using systemd mount directives and explicit read-only binds for the installed runtime, catalog, dependency closure, CA/resolver configuration and minimal OS identity files. Bind only this unit's StateDirectory writable; provide private tmp/dev/proc and runtime sockets. Hide host `/home`, `/root`, `/run`, `/tmp`, `/var`, `/opt`, `/srv`, `/mnt`, `/media` and arbitrary `/etc` content except named required mounts. Preserve systemd's credential and notification mounts. Do not mount all `/` or broad operator directories read-only and call that confidentiality. Read-only executable/library directories may be shared only when the operator manifest establishes that they contain runtime material rather than private state. No copied rootfs is produced: the configuration mounts approved installed artifacts directly. Pin and review the dependency closure before later native activation; missing dependency yields unavailable, not a broad fallback mount. Executable pins must not be writable by the agent or updated by native auto-update.

**Network default and prerequisite N1:** ship this new execution configuration with `PrivateNetwork=yes` and no internet-capable namespace override. Private network isolation also separates abstract Unix sockets; filesystem hiding alone does not do that. Provider/login/model attempts under this default report unavailable; an explicit network-disabled condition may refuse the provider-facing subprocess before it starts. That preflight must not replace the implemented action or its synthetic tests.

N1 belongs to #3719 and gates online activation, not this source packet. An operator-approved policy must specify the namespace, DNS destination/transport, permitted provider and relay destinations, redirects, IPv4/IPv6, and denial of host/sibling/local/metadata addresses, including the host's public addresses. Recommended later option: existing systemd `NetworkNamespacePath` bound to an operator-provisioned namespace with reviewed routing/firewall. No namespace provisioning, firewall framework, proxy, guessed provider allowlist or DNS policy is authorized here. A shared namespace between agents must also address abstract sockets and agent-to-agent reachability; it is not automatically acceptable. Keep the default disabled until that policy and native denial/positive tests exist.

## F3: fixed native actions and truthful discovery

### Invocation and local operator interface

- Login: a root-only operator-local frontend to `buzz-host-activate`, selecting an already prepared managed agent by validated opaque unit ID and displaying the corresponding public agent key before action. Resolve only the root-owned prepared descriptor; refuse unknown, legacy, fenced, stale or conflicting instances. Invoke the catalog-pinned Grok executable with exactly `login --device-auth` in that unit. No generic terminal, provider-specific OAuth code, token parsing, API fallback, copied credentials or user-shell execution.
- Models: the installed catalog-pinned `buzz-acp` with `models --json`, fixed `BUZZ_ACP_AGENT_COMMAND` set to the verified adapter, and catalog-approved args. Grok's approved args are `agent --always-approve stdio` from the existing preset/mechanism receipt. Same HOME/GROK_HOME/cwd/mount/network context as login and conversation. No prompt, model turn, relay connection, or MCP servers during discovery.
- Conversation: the existing harness launch and bounded configuration projection. Keep inactivity exit zero and all normal per-turn protections; F4 below makes configured model selection strict.

Expose only named helper actions required to start/observe/cancel finite modes. Login initiation/output is root-local, never owner-relay callable. The existing controller peer may request models and read only a sanitized typed result. It cannot request raw login output or arbitrary runtime execution. Use short helper transactions: a ten-minute login must not hold the global helper lock or consume its 100-second socket-service deadline. Start returns an action correlation; observation/cancel rechecks it and the current unit/cleanup state. The operator frontend owns bounded polling and Ctrl-C cancellation; disconnect/expiry leaves no unbounded login.

The runtime supervisor captures finite-mode stdout/stderr concurrently with a combined 64 KiB ceiling, models deadline 60 seconds and login deadline 10 minutes. Overflow, timeout and parse failure are explicit non-success and stop the process tree. Login URL/code output goes only to the private operator terminal; no journal, relay event, audit artifact or ordinary status includes it. A bounded private temporary result/output location is allowed; remove login output after completion/cancel/expiry. Root reads from that location must use anchored no-follow/regular-file/size/ownership checks so an agent-controlled symlink cannot turn the helper into an operator/sibling-file reader. Fixed structured reason codes cross the relay; raw provider output does not.

Separate observations instead of inventing an authentication predicate:

| Field/state | Meaning |
|---|---|
| Installation supported/unsupported/unavailable | Root-approved executable/hash and harness mapping observation; never authentication. |
| Native login `not-observed`, `in-progress`, `succeeded`, `cancelled`, `failed` | Outcome of this agent's fixed native login invocation with timestamp. Native success is evidence of that command, not proof of entitlement, refresh or chat. |
| Models `available`, `empty`, `unavailable`, `unsupported` | Valid bounded ACP projection, successful-empty projection, execution/transport/parse failure, or unavailable metadata mechanism respectively. |
| Derived `needs-login` | No successful native login observation yet, or a specifically evidenced native authentication-required outcome; never classify every error as missing login. |
| Derived `model-pending`, `selection-invalid`, `stale` | No selected model, selection absent/rejected in fresh session, or observation deadline/scope/catalog mismatch. Keep the user's saved selection visible for correction. |

Under network-disabled configuration, online readiness is unavailable even if old state exists. A prior native login success plus a current model response may be presented as those two facts; do not label it verified subscription readiness. Actual login/credential persistence/refresh and subscription-backed conversation remain #3722 pilot observations. No credential-file existence heuristic or desktop unknown-runtime `Ready` is permitted. An error after prior success invalidates launchability without deleting native credentials.

### Immutable per-agent observation transport

Use existing `Deploy { model: PendingLogin }` as preparation while the new agent lacks a model. Preparation creates the stable private context and runs fixed models discovery. Its terminal `NeedsLogin` receipt includes a typed private observation; the outcome name remains a legacy provisioning state, while the observation distinguishes login-required from model-pending/unavailable. Do not change a terminal receipt after native login.

An explicit refresh is another existing Deploy(PendingLogin) operation at the next revision, retaining identity, placement, unit and HOME. Refresh is supported only for the nonlaunchable/inactive preparation phase. Reject it before helper preparation can disable or stop an already running conversation. Same-operation retry replays the exact saved result and never re-executes discovery; fresh observation requires a new operation. This is a bounded pilot preparation flow, not a general refresh of running agents. The next Windows checkpoint connects its refresh affordance to this existing operation sequence.

Keep `Header::Result { result: DeploymentResult }` unchanged. Add an encrypted result-body wrapper containing that exact result and optional discovery observation. The wrapper's public result must equal the signed header. Preserve legacy result decoding and the existing result-only accessor; add a typed body accessor used by paired-owner. No model IDs, auth observations, login URLs, tokens or raw diagnostics enter public tags/header. Expired receipts remain historical evidence and cannot authorize launch. A successful login does not extend an old model observation's freshness.

## Judgment calls, prerequisites and stop conditions

- **N1, unresolved online installation policy:** source default is isolated/no-network; later operator namespace/DNS/destination policy and native evidence are required before live activation. Conductor routes under existing #3719. No separate prerequisite blocks writing the source bridge.
- **Per-operation discovery:** immutable preparation/refresh result uses existing operation/revision machinery. It avoids lossy host-status rotation and new per-agent storage. General running-agent model refresh is outside this pilot; if it becomes required, return its storage/authorization design separately rather than stopping conversations to refresh.
- **Native auth semantics:** no available receipt proves Grok models output certifies entitlement. Return native login and model observations separately. Any demand for stronger automated readiness without native evidence goes back to #3722; do not parse tokens or implement a provider API.
- **One-mode service design:** if finite actions cannot be made non-restarting without arbitrary unit overrides or weakened ownership, return the exact systemd constraint and smallest alternative before building another service control plane.
- **Mount closure:** if the real approved runtime requires private operator directories, existing credentials, broad mutable host mounts, or unbounded helper commands, stop and name that missing installation prerequisite. Missing dependencies are errors, not permission to relax isolation.
