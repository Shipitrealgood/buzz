## Concrete D mechanism, conditional on that choice

This section bounds the possible change; it deliberately stops short of an executor-ready design while the choice is pending.

**Verified platform semantics (read, not native tests):** installed `/usr/share/man/man5/systemd.exec.5.gz`, sections `PrivateNetwork=`, `NetworkNamespacePath=` and `RootDirectory=`, say a named namespace must exist when processes fork; NetworkNamespacePath overrides PrivateNetwork; network namespaces separate abstract Unix sockets; filesystem sockets remain a mount boundary. RootDirectory with NotifyAccess receives the notification mount. Installed `ip-netns(8)` explains that `ip netns exec` supplies `/etc/netns` binds; systemd namespace entry alone is not that DNS mount operation. Installed `network_namespaces(7)` describes separate routes/firewalls/socket namespace. [Upstream nft manual](https://netfilter.org/projects/nftables/manpage.html) distinguishes input, forward and output hooks and the IPv4/IPv6 inet family. These mechanics support the proposal, not proof of effective rules on netcup.

1. Keep the existing empty RootDirectory and systemd-owned state/runtime/credentials. Supply explicit root-owned resolver configuration inside that filesystem view; do not inherit host stub resolver, search domains, private DNS sockets or `/etc/hosts` private aliases. Keep standard TLS verification. Operator chooses public IPv4 resolver addresses; no guessed provider destination list.
2. Each canonical agent gets its own named network namespace and veth; no shared namespace between agents and no host-network fallback. Use NetworkNamespacePath through an exact reviewed online configuration. Retain the shipped disabled configuration. All three runtime modes enter the same per-agent policy; own loopback may serve that agent's processes, never host or sibling loopback.
3. A small **root-only oneshot dependency**, invoked by the existing helper binary with fixed selectors, creates that unit's namespace/link and scoped nftables state before the agent starts. It is not a daemon, proxy or general network manager. The helper owns automatic creation/retry/cleanup; requiring the operator to manually create a namespace for each new agent would leave the feature incomplete.
4. Deny by default in the agent namespace. Allow only selected-resolver TCP/UDP 53 and public IPv4 TCP 443, with return traffic. Deny all IPv6, including mapped-address bypass attempts; do not rely on an absent default IPv6 route. Deny private, loopback-to-host, link-local, multicast, reserved/non-global, deployment metadata and all host/sibling/co-resident destinations. Runtime has no NET_ADMIN/NET_RAW privilege and cannot join/create another namespace. Maintain socket/mount restrictions already in the canonical unit.
5. Host-side rules match only owned veth traffic. Drop host input regardless of destination address (including host public addresses), and filter forwarding **after destination NAT** against the forbidden destination inventory and the approved uplink. This must cover Docker/container bridges, VPN/private routes and public-address hairpins. NAT, if needed, is confined to the owned source/link and uplink. No global ruleset flush, unrelated chain replacement or blanket forward acceptance. Existing host firewall policy can still deny traffic; an nft accept is not a promise to override other chains. Host forwarding prerequisites are checked and surfaced, not silently changed.
6. DNS answers do not grant access: an A answer or redirect to a denied destination remains denied. AAAA cannot create IPv6 access. Redirects to another public IPv4 HTTPS destination are permitted under D; redirects to HTTP/private/local are blocked by the destination/port policy. DNS UDP truncation may retry TCP 53 only to the chosen resolvers. A resolver outage fails normally; no host DNS fallback. DoH over public 443 remains possible under D and does not bypass destination denials.

Root remains trusted to install and preserve this policy. This does not protect against an administrator deleting rules, changing routes or substituting binaries. The future manifest must identify external/NAT host addresses and any provider-specific metadata endpoints that ordinary private ranges do not cover. Those values are deployment evidence, not invented constants. If the target inventory cannot establish the denied boundary, online activation remains held.

### Lifecycle obligations for the eventual executable spec

- **Create/start:** immutable prepared managed instance and root-approved configuration only; derive resource names from its existing unit ID. Check exact owned unit/drop-ins, namespace/link/table ownership and collision-free address assignment before effects. No client-provided path, shell, interface, DNS or firewall selector. Namespace/link stay disconnected until both namespace and host protections exist. Missing/invalid policy, unsupported features or any setup failure prevents agent launch.
- **Retry/partial failure:** retain enough root-owned custody to recognize exact partial resources and clean/rebuild them idempotently. Foreign resources cause refusal, never deletion/adoption. Serialize network effects independently of the activation directory flock: [activation holds that lock](../../crates/buzz-hostd/src/activation.rs:171) while [waiting for systemctl](../../crates/buzz-hostd/src/activation.rs:382); a dependency taking the same lock deadlocks. No second journal/controller is warranted.
- **Cleanup:** existing fence precedes effects. Confirm agent cgroup empty, then stop/reap the network dependency and remove only owned link/namespace/rules. Unlinking a namespace name alone does not kill users of it (`ip-netns(8)`). Network cleanup failure remains an error/retry obligation; no cleaned acknowledgement while the boundary remains launchable. Preserve the existing retained-data/tombstone policy.
- **Finite actions/restart:** preserve exact Restart=no handling and local login authority, busy exclusion and no finite enable-on-boot. Network dependency may be recreated between modes; unit/HOME and policy stay the same. Conversation restart must require successful network setup again; no permissive fallback.
- **Boot:** enabled conversation starts only after the oneshot has recreated policy and namespace; deliberate stop/deletion and finite modes must not resurrect. Missing policy/network dependencies at boot fail closed. Isolated-host reboot must verify this ordering and retained state. A live netcup reboot is neither required now nor authorized.
- **Installation boundary:** runtime, network policy and unit artifacts are pinned together. Actual installed binary paths, closure inventory, interface/address allocation, exact nft chain ordering, dependency stop ordering and partial-state representation must be finalized after the policy choice. Their absence is why this is a decision packet rather than a ready implementation spec.
